> v1 声称"时钟帧上传量 14400 → 2000、省 86%"，**经审查该基线不成立**。
> 本版逐条列出被推翻的陈述、修正依据（git 提交 + 仓库实测文档 + 代码行号），

## 1. 审查后仍然成立的部分

以下经逐行复核，属实：

**1.1 子矩形上传的正确性（v1 §1）**
`copy_rect_to_dib`（1454 行）对 DIB 是原址覆盖，未拷贝区域保留上一帧内容；`prcDirty` 只让 DWM 重混该子区。所以"只上传子矩形"在语义上正确——这是全部收益的前提。

**1.2 双位图分离（v1 §4）—— 本条是设计上最关键的一步**
`compute_dirty_in` 维护两张位图：
- `content_changed[i]`：hash 真的变了
- `changed[i]`：`content_changed` 经邻接传播扩散（服务 GDI `paint` 跳格重画，防 `clear_rect` 擦掉邻居墨迹的残影）

而 `dirty_components` **只吃 `content_changed`**（853 行：`let rects = dirty_components(cells, &content_changed);`）。
邻居内容没变，重画出的像素与上一帧一致，上传它纯属浪费——所以传播不扩大上传矩形。属实且必要。

**1.3 失败双保险（v1 §5）**
`NEEDS_FULL_REUPLOAD`（一次性 `swap` 消费）+ 帧指纹回滚，缺一会冻结。代码位置：1115 / 1225 / 791。属实。

**1.4 边界处理（v1 §6）**
`MAX_DIRTY_RECTS = 8` 触顶折叠 Full（520 / 851）；`copy_rect_to_dib` 与 `ulw_indirect_rect` 各自做 `(0,0,width,height)` 钳制（1455-1461 / 1149-1157）；D2D 直接画进 DIB 无需拷贝（1190-1220）。属实。

## 2. 修正后的收益模型

**记号**
- `B` = 整窗面积（W×H）
- `C` = 本帧内容变化格集合（`content_changed` 为真的格）
- `b(c)` = 格 `c` 的包围盒（`bbox_x, y, bbox_x+w, y+h`）
- `C = C₁ ⊔ … ⊔ C_k`：按"包围盒相交"关系做的连通分量划分
- `R_i = bbox(∪_{c∈Cᵢ} b(c))`，`A = Σ|R_i|`

**旧模型上传量**：`U_old = |bbox(∪_{c∈C} b(c))|`
**新模型上传量**：`U_new = A`

**（a）单格变化（k=1 且 |C|=1）**
`U_old = |b(c)| = U_new`。**完全相同，收益 0。**
→ 这直接推翻 v1 表格的前三行（时钟跳秒、CPU 数值单独变化等）。

**（b）多格但同属一个分量（k=1）**
`U_old = R₁ = U_new`。收益 0。

**（c）k≥2 且各分量的包围盒两两面积不相交**
`R₁…R_k` 是 `bbox(∪C)` 内互不重叠的子矩形 ⇒ `A = Σ|R_i| < |bbox(∪C)| = U_old`（严格小于，因为 k≥2 时上包里至少含一个不属于任何 `R_i` 的空隙像素……严格地说：只要上包中存在像素不属于任何 `R_i`，不等式就严格）。
**收益 = 1 − A/|bbox(∪C)| > 0。**

**横条布局下（c）的条件自动满足**：所有 cell 在同一行（`y` 相同、`h` 相同），非相交要求退化为 x 区间不重叠；不同分量的 x 区间互不重叠 ⇒ 包围盒两两面积不相交。所以悬浮窗的 strip/vertical 单列布局下，k≥2 时**必然**有严格收益。

**（d）一般布局（本仓不出现，但要说清）**
分量包围盒可能互相重叠（对角排列的 cell），此时可能 `A > |bbox(∪C)|`，即多矩形的总面积反而大于旧的上包。这不是"上传得更多"（重叠区域传两次是同一份 DIB 内容，无害），但会放大系统调用次数。`MAX_DIRTY_RECTS` 是这一路退化的兜底。**v1 把这个一般性不等式写成了无条件的，是错的。**

## 3. 收益的充要条件（可判定）

```
收益 > 0  ⟺  本帧存在 ≥2 个连通分量
           ⟺  至少两个变化格，且它们不通过"包围盒相交"链相连
```

工程上就是：**同一帧里有多个不相邻的格同时变化**。

这在悬浮窗上什么时候发生？
- 时钟每秒变，而数值类格（CPU/GPU/占用/功耗…）按采样节奏变 → 两者落在同一帧时，就是 k≥2。
- 多指标同时跳变（采样值普遍变化的那一秒）→ k 更大。
- 只有时钟变的那一秒 → k=1，**收益 0**（这正是 v1 错标的场景）。

所以这个优化的定位应是：**把"多格同帧变化"的帧从"上包矩形（可能横跨半窗甚至整窗）"降到"各格自身"**，而不是改善单格帧。

## 4. v1 漏掉的关键风险：k 次系统调用 vs 1 次

新模型的代价被 v1 完全忽略了：

| | 旧模型 | 新模型 |
|---|---|---|
| `copy_rect_to_dib` memcpy 面积 | `|bbox(∪C)|` | `A`（≤ 上包） |
| DWM 重混面积 | `|bbox(∪C)|` | `A` |
| `UpdateLayeredWindowIndirect` 调用次数 | **1** | **k** |

净收益 ≈ `Δ(memcpy + 重混面积)` − `(k−1) × (ULWIndirect 固定开销)`

ULWIndirect 的固定开销包括：用户态→内核切换、DWM 层的窗口更新入队、图层重合成调度。这部分**不随矩形面积缩小而缩小**，是每次调用的常数项。

**结论**：净收益为正**不是结构必真**，依赖 `Δ面积` 与固定开销的相对量级。
- k=1 时二者完全相同 → **无回归**（这是可以确定的）。
- k≥2 时需要一个前提：**面积节省量级显著大于 (k−1) 个固定开销**。悬浮窗是 485×40 的小窗，重混面积从"半窗(≈9700px)"降到"两格(≈5000px)"这种量级的节省是否真能盖过 1 次额外 syscall —— **没有实机数字前不能断言**。v1 直接给出"≤40%" 的目标值，属于无依据的外推。

测量方法（仓库已具备）：`tools/ab_perf.ps1` 双跑 + `seg_upload pct=… n=…` 聚合行，对比 `n=1` 与 `n≥2` 帧的 p50/p99。

## 5. 作用域声明（v1 未写清）

- 本优化只作用于**上屏段 `seg_upload`**：`copy_rect_to_dib` 的 memcpy 面积 + ULWIndirect 的 `prcDirty` 面积。
- **不影响 `seg_draw`**：D2D 路径每帧仍 `clear()` + `paint_cells(全部)`（该句在 `render_d2d` 内原样保留，二期才谈部分重绘）。P0 实测 `seg_draw` p50=1274µs 是帧成本大头，本优化**不动它**，所以不要期望帧 p50 有 1274µs 量级的改善。
- 无变化帧跳过上屏的分支实际不可达（帧指纹在上层已拦），不计入收益。

## 6. 可证伪的验收方法（替换 v1 的"预期 pct ≤40"）

| 断言 | 判定方法 | 通过条件 |
|---|---|---|
| **A. 单格帧无回归** | 日志筛 `Rects(n=1)` 帧的 pct 与 `seg_upload` | 与改动前同场景 pct 相同（旧模型单格也是该格 bbox） |
| **B. 多格帧面积下降** | 筛 `Rects(n≥2)` 帧，比较 `pct=Σ面积/整窗` 与"仅时钟变化帧"的 pct | 多格帧 pct 明显低于"该帧最左与最右变化格跨距/整窗"（即旧上包占比） |
| **C. 多格帧耗时未变差** | A/B 双跑（`AAXSYSPULSE_NODIRTY=1` 为对照）的 `seg_upload` p50/p99 | n≥2 帧的 p50 不劣于对照；若劣化 → §4 的固定开销吃掉收益，需回退或限制 k |
| **D. 无残影** | 人工：盯右对齐数值格左缘、时钟走秒 | bbox_x 覆盖正确（既有回归点） |

**最重要的诚实结论**：B 是我预期的收益（有结构依据），C 是必须先测的前置条件（v1 未提）。若 C 不通过，本改动的净收益为负，应回退或加"k≥2 且面积节省超过阈值才拆"的门槛。
