# 悬浮窗性能恢复计划（从"感觉很好"到"数字很好"）

> 2026-09-12 · 依据：PERF_ANALYSIS.md 顶部 A/B 实测勘误（提交 3e960c1）。
> **目标重定义**："教科书级"不再是形容词，而是 5 个可测量验收门槛（见 §5）。

## P2 帧成本攻坚（**P0 数据出来才立项**，预计 1-2 天）

按 P0 分解结果三选一（预期收益排序）：

| 若大头是… | 动作 | 预期 |
|---|---|---|
| `seg_draw`（D2D 绘制） | 检查 offscreen 清屏范围（全清 vs 脏区清）、EndDraw 边界次数、字体缓存命中率 | p50 3.24→1ms 级 |
| `seg_upload`（present） | **先看 0.3 结果**：脏区≈整窗 → 接受现状；脏区小但没省 → 修 prcDirty 分支 | 视 0.3 |
| `seg_layout`（layout/build_cells） | StrBuf/RowList 已优化过；查新增 cell 源（时钟行等），考虑布局结果缓存（快照未变直接复用） | 事件驱动下收益有限 |

**红线**：若 P0 分解显示三段均衡且无单点肥肉，P2 直接关闭——1.3% CPU 的悬浮窗没有资格烧更多工程时间。

## 5. "教科书级"的最终验收定义

| 门槛 | 目标值 |
|---|---|
| ① 可观测 | perf.log 聚合反映生产引擎，每帧 4 段分解 |
| ② 帧成本 | p50 ≤ 1.5ms **或** P0 证明已无单点肥肉（二选一即达标） |
| ③ 尾延迟 | p99 < 16ms，或尾刺根因明确归属外部（DWM/驱动）并文档化 |
| ④ 韧性 | D2D 失败率 <0.5%，panic/锁屏/唤醒三路径闭环（BUG 清单清零） |
| ⑤ 可复现 | `tools/ab_perf.ps1` 一条命令出 A/B 分位数表 |

**诚实预期**：悬浮窗当前 1.3% 单核，本计划的主要回报是③④（卡顿与自愈）和①（从此每个性能声明都有数字），②只有在 P0 分解出单点肥肉时才值得追。
