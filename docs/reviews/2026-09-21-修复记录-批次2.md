## 1. P0-11 安装/卸载缺互斥

- **症状**：安装页快速点击、或"重试"连点，可让两次 `install_run` 并发跑在同一批文件与服务上；卸载同理。
- **根因**：`install_run` / `uninstall_run` 无任何状态闸门，Tauri 命令每个调用各起一线程。
- **如何修正**：`guide-app/src-tauri/src/lib.rs`
  - `static INSTALL_BUSY` / `UNINSTALL_BUSY: AtomicBool` + `struct BusyGuard`（`try_lock` 用 `swap(true, SeqCst)`，`Drop` 里复位）；
  - 两个命令开头 `BusyGuard::try_lock(...).ok_or_else(|| GuideError::new("INSTALL_BUSY", "安装已经在进行中").with_hint("请等待当前安装结束，或取消后再重试。"))?`。
  - 自查记录：`try_lock` 初稿里误写了一次多余的 `flag.swap(false, ..)`（会把刚拿到的锁立刻释放），已删。
- **验收**：并发第二次调用立刻拿到 `INSTALL_BUSY` 而不是排队；命令返回或 panic 后标志自动释放（`Drop`）。

## 2. P0-9 卸载必须逐步如实回报 + 优雅关闭（含 3.1.9 / 5.4.2 / 8.9）

- **症状**：`run_uninstall` 九步全部 `.ok()` 丢弃结果、返回 `()`，界面永远只有一句"卸载完成"；卸载键**先**删（前面失败就没了重试入口）；第一步 `taskkill /F /IM AAXSysPulse.exe` 裸名按映像强杀。
- **如何修正**
  - `guide-app/src-tauri/src/install.rs`：新增 `StepResult { step, status: ok|skip|fail, detail? }` + `UninstallReport`（`record/ok/ok_with/skip/fail`），`run_uninstall(keep_config) -> Vec<StepResult>`；顺序固定 9 步：关闭主程序 → 停止服务 → 删除服务 → 删除驱动目录 → 删除计划任务 → 删除 Run 键 → 删除快捷方式 → 删除安装目录 → **删除卸载注册放最后**（前面失败时用户仍能从"添加或删除程序"重试）。
  - 失败语义收紧：`sc stop/delete` 返回错误现在记 **fail**（旧实现记"跳过"）；`keep_config` 下的残留路径列进 `detail`；`DeleteFileW`/`RegDeleteValueW`/`RegDeleteTreeW` 三分支（成功 / `ERROR_FILE_NOT_FOUND` 视作无需处理 / 其余 fail）。
  - **taskkill → 优雅关闭**：`guide-app/src-tauri/src/process.rs` 新增 `request_main_close()`（`FindWindowW("AAXSysPulse_WndClass")` → `PostMessageW(hwnd, WM_CLOSE, 0, 0)`）与 `wait_main_exit(3s)`（100ms 轮询）；`taskkill` 调用整体移除。
    - **依据（已读码核实）**：主程序 `window.rs` 无 `WM_CLOSE` 自定义处理 → `DefWindowProcW` 销毁窗口 → `WM_DESTROY` 里 `KillTimer`×3、`invalidate_dib_cache`、`OVERLAY_HWND.store(0)`、`tray::remove`、`PostQuitMessage(0)` ⇒ `WM_CLOSE` 就是正常退出，无需新增 `WM_QUIT_CLEAN`。
  - **"主程序是否在跑"的唯一判据**也收敛到 `process.rs`：`main_process_pid()` = `FindWindowW` + `GetWindowThreadProcessId`，取代按进程名 `contains` 匹配（旧判据会把引导自己算成主程序）。
  - `lib.rs::uninstall_run` 返回 `{ done: all_done, steps }`；`useGuide.js::runUninstall` 存 `state.uninstall.steps`（命令整体失败时合成一条 `fail`）。
  - `GuideWizard.vue`：完成 sheet 标题按 `uninstallAllOk` 分成「卸载完成」/「部分步骤没能完成」，`<ul class="uninstall-steps">` 逐条 名称 + 状态（已完成/无需处理/未完成）+ detail；`wizard.css` 加 `is-ok`→`--success`、`is-fail`→`--danger`。
- **验收**：任一步失败 ⇒ 标题变「部分步骤没能完成」且该项标红；全成功才说"完成"；卸载时不再出现 `taskkill` 进程。

## 10. 附带：`guide_delete_self` 重写（3.1.12，报告结论被证伪）

- **旧实现（实测，见 §13）**：写 `%TEMP%\delete_guide.bat` + `cmd /c start /b`，对**正在运行的自身镜像**执行 `del` 必然失败，且返回值被 `.ok()` 丢弃 ⇒ 用户点「删除引导文件」永远毫无反应，还留下一个可预测名、可被抢占的临时 bat。
- **如何修正**：`lib.rs` 新增 `guide_delete_self() -> CmdResult<String>`：`GuideState::reset()` → 清掉上次残留的 `.old` → `std::fs::rename(exe, exe + ".old")`（Windows 允许改名运行中的镜像，不允许删除）→ `MoveFileExW(target, PCWSTR::null(), MOVEFILE_DELAY_UNTIL_REBOOT)`；返回**一句人话**（"引导程序已停用，将在下次开机时彻底删除。" / "引导程序当前无法改名（文件被占用），已安排在下次开机时删除。"），失败返回 `DELETE_SELF_FAILED` + hint。
- **前端**：`deleteGuideFiles()` 成功/失败都 notify（不再静默）；P14 确认 sheet 文案改为与实现一致 —— "将删除引导程序本身和它的引导进度存档，**下次开机时生效**…主程序的设置不受影响；要整体卸载请在设置里选「卸载」。"（原文案"删除配置与进度文件"是错的：配置归主程序）。

## 11. 附带：`app_quit_all` 不再 `std::process::exit(0)`（9.9）

- **症状**：命令内直接 `process::exit` ⇒ 前端那次 `await` 永不 settle，`finally` 之后的逻辑不跑，退出前的落盘顺序不可控。
- **如何修正**：`lib.rs::app_quit_all(app: tauri::AppHandle)` 起线程 `sleep(120ms)` → `app.exit(0)`，命令立即 `Ok(())`；`bridge.js` 的 `quitAll()` 因此能正常返回，`beforeunload` 之外的路径也不再被"进程先死"抢跑。

  //! 使用 notify crate 监控配置目录变更
  use notify::{Config, Event, RecommendedWatcher, RecursiveMode, Watcher};
  use std::path::PathBuf; use std::sync::mpsc; use std::thread; use std::time::Duration;
  pub type ConfigChangeCallback = Box<dyn Fn(WatchEvent) + Send + 'static>;
  #[derive(Debug, Clone)] pub enum WatchEvent { ConfigChanged(String), Error(String) }
  /// 配置监听器
  pub struct ConfigWatcher { _watcher: RecommendedWatcher }
  impl ConfigWatcher {
      /// 启动配置目录监听
      pub fn start<F>(config_dir: PathBuf, callback: F) -> Result<Self, String>
      where F: Fn(WatchEvent) + Send + 'static {
          let (tx, rx) = mpsc::channel();
          let mut watcher = RecommendedWatcher::new(
              move |res: Result<Event, notify::Error>| { if let Ok(event) = res { let _ = tx.send(event); } },

              .map_err(|e| format!("Failed to watch directory: {}", e))?;
          thread::spawn(move || { for res in rx { match res.kind {
              notify::EventKind::Modify(_) | notify::EventKind::Create(_) => { for path in res.paths {
                  if let Some(name) = path.file_name() { let name = name.to_string_lossy().to_string();

              _ => {} } } });
          Ok(Self { _watcher: watcher })
      }
  }
